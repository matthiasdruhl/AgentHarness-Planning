2. **Normative relationships/security/math:** **this file** defines semantic invariants not expressible in JSON Schema. Implement Zod `.superRefine` or equivalent and test them, rather than assuming parsing suffices.
3. [docs/03](03-data-contracts.md) owns artifact meanings; [docs/04](04-api-contracts.md) owns endpoint behavior and HTTP error mapping; [docs/09](09-evaluation-plan.md) owns experimental validity; [docs/10](10-security-and-privacy.md) owns host trust.
4. Historical compact examples in other documents are **illustrative, not competing contracts**. An incompatible shape change requires a literal `v2` schema, migration notes, fixture updates, and consumer tests. No silent `v1` schema drift after app implementation begins; pin the exact merged planning SHA in the separate app repo.

### Shared rules

- All top-level artifacts carry exact version const and stable ID where defined. Strict reject unknown object keys *including nested keys*; JSON request maximum 65,536 UTF-8 bytes **before** parsing; bound JSON structure by schema (including recursion prevention). IDs unique within their specified graph, run or study scopes. ISO UTC timestamps must normalize to `YYYY-MM-DDTHH:mm:ss.sssZ` on emission; parsers may accept equivalent valid ISO UTC with Z. `start <= end` by actual instant, not string lexical order. No `NaN`, infinities, negative costs, path escapes or symlink traversal.
- Content-addressed hashes: lower-case 64-character hex SHA-256 over canonical byte content. Git commit IDs are separate 40-char lower-case SHA-1-shaped identities for this pinned Git repo; never substitute source Git SHA for `evaluatedTreeSha256`. Hash tree by a **documented deterministic manifest** of sorted normalized in-scope relative paths and file-content hashes (exclude .git, host secrets, caches, generated reports); do not hash machine-dependent absolute paths or unstable mtimes.
- `source.path`, candidate modules, evidence paths and workspace paths must stay under an approved root after realpath/symlink validation. The regex in structural schema alone does not stop symlink escapes; never hand client-supplied file paths to a server loader. All model-proposed operations are advisory allowlisted enum data, never commands.
- **Provenance dimensions are independent:** provider `mode = live|recorded|template` means model output origin; `evidenceOrigin = measured|none` denotes actual protected evaluator measurement; `presentationMode = live|recorded` denotes *display* channel. `recorded + measured` is valid when replaying real captured evidence, but synthetic fixture JSON is not actual measured data. Unknown observation metrics are **null**, not fabricated zero. Model-generated estimates always state `modeled_effort_points_v1`, never "measured".

## Intent and scenario invariants

- `IntentV1.status=confirmed` **only** when a real user confirms the text, sets `source.kind=user_confirmed`, and increments `revision >= 1`. Meta suggestions are `IntentDraftV1`, never autonomously confirmed. `rejected` and `tentative` cannot drive a production recommendation.
- Consent is for the exact request payload; only send opt-in text or approved minimal graph summary to Meta. A provider `mode=live` requires actual observed eligible model response; recorded/template modes never imply an external inference call.
- On edit/revoke: advance the intent revision and invalidate graph-conditioned scenarios, candidate analyses, decisions and certificates referencing old `(intentId, revision)`; old historical experiment records stay immutable but are labeled stale for the *current* recommendation.
- `ScenarioV1.intentIds` must refer to existing **confirmed** revisions authorized for this run; `baselineCommit` must match graph and candidates. A genuine `origin=evaluator_heldout` scenario must not reach any app/model prompt, developer preview or agent workspace before freeze.
- Unique scenario and acceptance IDs; reject dangling refs and mismatched frozen baseline. Public docs' S3 description is **not** a secret heldout task.

## Architecture, graph and decision invariants

- Graph modules have unique `id` and `path`; edges must reference existing module IDs (cycles are **permitted** and traversals must terminate). Route path analysis cannot certify runtime integration; unresolved dynamic paths remain unknown. Candidate `baselineCommit` equals graph `repoCommit`. At least status-quo A (empty changePlan, upfront 0) and one meaningful alternative B are required. No Meta statement can grant trusted oracle status.
- **Fixed v1 upfront action rubric:** `introduce_boundary = 3`, `extract_module = 2`, `move_module = 2`, `add_interface = 2`, `leave_unchanged = 0`. `candidate.estimatedUpfrontCost` MUST equal sum of those action weights; reviewed plan items are unique by (module, action) and cannot contain commands. Zero upfront for status quo A. Constraints must reference approved repo-relative glob patterns only.
- **Fixed v1 scenario effort rubric:** `downstreamCost = 2 × number of unique basis.projectedChangedModules + basis.projectedRouteChanges + 2 × basis.unresolvedRelevantDependencies`. Changed modules must be normalized repo-relative paths that appear in the graph **or** have an explicit reviewed candidate change-plan entry; duplicates forbidden. The `basis.source` is an explicit projection, not observed future work. A score's `upfrontCost` must equal its candidate's scored upfront cost; `totalCost = upfrontCost + downstreamCost`; `regret(c,s) = totalCost(c,s) - min_{all eligible candidates} totalCost(c',s)`. The result matrix is **complete** for every candidate × scenario with no duplicate pairs.
- Default recommendation minimizes **max scenario regret**; ties choose lower total upfront cost, then lexically lowest candidate ID for deterministic behavior. If any relevant basis is unknown, source is unverifiable, IDs mismatch, or alternatives cannot be compared, emit **`perScenario:[]`, `recommendationId:null`, plus at least one clear limitation**. A partially filled nonempty candidate×scenario matrix is invalid; never invent zeros or ordinal arithmetic.
- A candidate's modeled upfront score includes every counted change; measured B upfront cost is separately recorded during real experiment and is **not** derived from these points.

## Protected evaluator and evidence state machine

- `CheckResultV1`: `runId` equals its parent run/verification/receipt run; IDs unique per run; pass exit code 0 and artifact hash present; fail exit code nonzero and artifact hash present; not_run exit code null; invalid cannot authenticate a success. Required-check IDs unique, subset of actual records, and exactly match evaluator-controlled pinned `requiredPolicySha256`. A passing optional check never substitutes for a missing required check.
- `EvaluatorReceiptV1`: issuer label alone is spoofable. Trusted receipt **only** if loaded from evaluator-controlled protected artifact root (or verified under an authenticated, separately managed key), bound to immutable final post-agent `evaluatedTreeSha256`, pinned `fixtureSha256`, evaluator and test-suite hashes, required policy hash, required check IDs, and canonical results artifact digest. Every relevant changed code/test/config/policy/fixture invalidates previous passing evidence. Client-supplied receipt/check IDs or SHA strings **never** establish authority.
- Digest algorithm: canonical JSON via **RFC 8785 JCS**; compute `checkArtifactSha256 = SHA256(JCS(all check records sorted by check.id))`; `receipt.integrity.manifestSha256 = SHA256(JCS(receipt with the leaf `integrity.manifestSha256` **omitted**, preserving `integrity.kind`))`. For exported `CertificateV1.artifactSha256`, compute `SHA256(JCS(certificate without its own `artifactSha256` field))`. Avoid self-hash cycles. Validation verifies actual stored bytes and JCS consistency. Certificates refer only to existing trusted run/verification/receipt IDs; hashes/IDs cross-check at load.
- **Verdict precedence:** no trusted fresh receipt → `INSUFFICIENT_EVIDENCE`; among correctly authenticated required results, **any trusted failure → REJECTED** even if others absent; all required unique checks present, valid and pass with matching receipt → `VERIFIED`; otherwise `INSUFFICIENT_EVIDENCE`. `VERIFIED` means *specified checks only*. `VerificationV1.origin=untrusted_preview` always returns `INSUFFICIENT_EVIDENCE`, `receiptId=null`; a public web route never upgrades it.
- `ExperimentRunV1.status=completed` means execution ended normally, **not** acceptance tests passed. Timed-out/blocked/cancelled runs cannot assert completed measurement. Actual source tree hash binds to evaluator receipt whenever both present. Check report provenance, clock order and artifacts. Do not assume mere existence of a hash proves credential isolation.

## Experiment manifest / causal language

- `PairManifestV1`: exactly variants A and B once each; both initially pass the same current-spec external oracle. Freeze scenario, hidden requirements (if any), agent/model/config, tool allowlist, input fixture, evaluator/policy and **same budgets** before downstream task. Different initial source trees are expected when testing architecture; record B's upfront preparation metrics. Include losses, failures and null measurements, not selected wins.
- `MetaComparisonManifestV1` is **separate** from the A/B architecture study. Give Meta and the strong template/roadmap-aware comparator the same permitted information and downstream coding-agent conditions; count model proposal overhead. Only these comparable outcomes may support "Meta improved" claims; a booking A/B result cannot attribute benefit to Meta.
- `evidenceOrigin=measured` is only allowed with actual audited run artifacts and trusted evaluator; synthetic positive fixtures in `contracts/examples` are **shape-only examples** and must never appear on a demo as measured runs.

## API authority and error behavior

- `POST /api/intents/interpret` and `POST /api/foresight/propose` require JSON `consent:true` and server-only eligible model configuration; consent does not imply a suggested intent was confirmed. Propose may use only `status=confirmed` user-approved intents. Evaluate is deterministic **pure** and refuses dangling graph/candidate/scenario references; no authority to launch an experiment.
- Responses match registry schemas directly, not a second undocumented envelope. `ProviderInfo` accurately describes real `live`, `recorded` or `template` origin. No model errors are silently hidden as successful inference.
- Web origin checks, hard request/body limits, per-endpoint budget/rate limits, abort/timeouts, no cache and safe diagnostic logging; no keys in response. In demo P0, use server-controlled allowlisted recording IDs (not arbitrary filesystem paths). No hosted arbitrary-shell, clone, judge test execution, `sbx`/Codex start or hidden grader endpoint.
- Optional `POST /api/verify/assess` may be omitted entirely; if present it returns `VerifyPreviewResponse.authoritative=false` and no trusted verdict. Hosted `GET /api/demo` returns recorded **sanitized** real evidence, not simulated evidence presented as true.
- `ApiError`: 400 `INVALID_REQUEST`; 413 `PAYLOAD_TOO_LARGE`; 422 `INVALID_REFERENCE` or `UNSUPPORTED_OPERATION` or `UNTRUSTED_EVIDENCE`; 429 `RATE_LIMITED`; 503 `PROVIDER_UNAVAILABLE`; 500 `INTERNAL_ERROR`. All errors use the same `api-error.v1` JSON envelope, stable `requestId`, safe message and retryable boolean; no raw stack/secret disclosure. GET methods other than defined routes and malformed content-type requests rejected.

## Additive Meta Scientist v1 extension (Oct 25, 2026)
Existing frozen record shapes and cost/evaluator verdict semantics **remain unchanged**. The [Meta Scientist protocol](META-ARCHITECTURE-SCIENTIST.md) adds separately versioned `meta-hypothesis.v1`, `meta-challenge.v1`, `scientist-evidence-summary.v1`, and `meta-evidence-interpretation.v1` plus three specifically registered POST endpoints. Exact structures are in [schema](../contracts/schemas/forecode-v1.schema.json), [API registry](../contracts/api-registry.json), and positive/negative fixtures. This additive extension may not override any evaluator, consent or holdout gate.
**Binding rules:** hypothesis must reference approved intent and candidate/graph baseline; challenge must reference a matching hypothesis/candidate, remain `proposed` and `model_generated_not_heldout`; recorded provider and nested provenance must match. Evidence summary is generated only from **server-allowlisted protected receipts** and sanitized check scopes; a client-chosen ID is not evidence authority. Hypothesize and challenge requests include an explicit non-heldout visibleScenario set; interpretation must look up **both** hypothesis and evidence summary from allowlisted server-owned records, not trust a client-supplied hypothesis body. Interpretation references the exact hypothesis and validated summary, remains `model_interpretation_only`, and cannot alter pass/fail or start an agent. Missing real evidence means the interpretation step is unavailable or honestly marked insufficient. A model-generated challenge is never an independent hidden holdout. See [Meta Scientist invariants](META-ARCHITECTURE-SCIENTIST.md).
