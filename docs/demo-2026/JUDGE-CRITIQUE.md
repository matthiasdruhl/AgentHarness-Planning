## Skeptical judge's questions

**“What would make this look like an ordinary AI wrapper?”** A long chat response, decorative graph and green certificate without traceable experimental evidence. A Meta logo or Muse Code development story does not answer that concern. S04–S06 must show the exact falsifiable prediction and a challenge to the preferred design; S08–S12 must reveal actual evidence or truthful missingness.

**“What part is genuinely different?”** The proposed scientific workflow binds a confirmed future need to competing architecture choices, an explicit disconfirmation condition, adversarial challenge, controlled implementation and an evaluator-owned outcome. The implemented report withholds unsupported decisions. Its novelty is the accountability of the workflow; claiming a superior algorithm, trained learning system or unique market position is unsupported.

**“Where is the strongest evidence?”** Today: E01 baseline source/prior browser validation; E03–E05 genuine retained Meta outputs; E11 actual fail-closed replay/report composition. E07 documents historical execution but its private comparative outcomes are not available to this demo. A future Path A would shift the strongest evidence to a disclosed exact-source protected comparison. No amount of unit-test count fills that slot.

**“Which scene would feel confusing or dishonest?”** Cutting from a newly typed requirement to a historical output without labeling the switch; showing the Case card as if it were an interactive booking app; calling conceptual trace a completed refactor; presenting a proposed cancellation weakness as an exploit; treating a shared-host signature as blind organizational review; displaying a historical receipt under a new study; or hiding unavailable evidence behind an animation. The shot list explicitly avoids all seven.

**“What must be cut to fit three minutes?”** Logo intro, account creation, terminal setup, provider latency, agent/sandbox maintenance details, extra scenarios, learning-loop/RL roadmap, Monte Carlo or calibrated probabilities, bonus-category pitches, optional model interpretation, full SHA narration, printing/export flows, and any general feature tour. Retain disclosure, one booking action, one prediction, one challenge, one evidence inspection and one report.

**“Why is an inconclusive report valuable?”** It makes the absence of proof actionable and avoids selling a premature refactor. That is a useful current behavior, but it does not validate the architecture hypothesis. The narrator must not turn “unknown” into a positive empirical result or an implicit KEEP recommendation.

## Written acceptance and factual-claim checklist

- [ ] A first-time viewer can state the developer's decision after 20 seconds; real booking action is visible immediately after 0:12.
- [ ] Opening identifies actual pre-event concept/planning and actual new event-built software. Owner has checked shown-work provenance and rights.
- [ ] Exactly one 180-second path is selected, with no additional bumper/credits; all bracketed A/B slots resolved from approved evidence or path downgraded.
- [ ] Model identity, origin, date and context remain inspectable. Recorded output is never called live; template is never called Meta inference.
- [ ] Hypothesis, falsifier, counterexample and their metric mismatch/limitations remain visible. Proposed risk is never stated as observed.
- [ ] Baseline conceptual graph, proposed B, source snapshot and measured final topology are not conflated.
- [ ] Every stated observation/number has its allowed original artifact; estimates and unknowns are labeled. No ordinal-to-hours conversion, budget-to-invoice conversion or omitted preparation cost.
- [ ] Public disclosure covers the exact shown projection/source paths/outcomes. No private historical result, diagnostic, hidden assertion, credential, host path or personal eligibility detail appears.
- [ ] Comparative claim has both actual baselines, same task/agent/tools/budgets/evaluator, source-bound receipts, complete attempts and predeclared criteria. Otherwise no winner.
- [ ] Both passing remains a correctness tie. Inconclusive is not KEEP; review-prepared is not automatic promotion.
- [ ] No claim Meta improved outcomes without separate equally informed control; no generalization beyond the scoped case.
- [ ] Optional interpretation omitted unless separately authorized genuine lineage/summary disclosure and fresh receipts exist. It can never replace evaluator verdict.
- [ ] Clean-session product/source/demo links, keyboard inspection and legibility verified later against approved release. Previous Chromium evidence is not Safari/manual screen-reader validation.
- [ ] Accepted waiver, unresolved eligibility/team, track/theme, repository/public access and portal/video format checked privately by owner; no disputed numerical weights cited.
- [ ] Recording has a separate explicit assignment. This planning PR has created no media, app changes, inference, experiment, protected-evidence changes, deployment or submission.
