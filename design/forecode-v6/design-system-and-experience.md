# ForeCode v6 — The Change Trace
**October 30, 2026 · Design-locked conceptual reference only.** This is not live Meta output, agent execution, source diff, or verifier evidence.

## Product north star

**The code works today. Will it survive what comes next?**

The Change Trace is ForeCode's defining interaction: a single human-confirmed future requirement travels through competing architecture paths, then resolves into an evidence-backed engineering Decision Report. It is a **shared visual grammar**, not a new evaluation engine or proof of propagation.

Preserve the established case (booking-v1 today; confirmed team/delegated permissions tomorrow), the four v5 workbenches, the research/fairness protocol, the existing read-only publication trust boundary, and the two distinct questions: Study F (B preparation versus A status quo) and optional Study M (Meta-informed B versus equally informed non-Meta C).

## Inviolable design rules

1. One future requirement diamond appears across landing, Lab, Tournament, and Time Machine. Same task identity, same visual location in the story.
2. Thin branching lines lead to aligned A and B architecture lanes. The paths never imply winning, speed, security, or measured results.
3. Dashed links and outlined nodes = conceptual/proposed. Solid observed-edit emphasis only when an authenticated source comparison actually exists.
4. The graph is a teaching and inspection instrument, not a diagram editor or a client-side grader.
5. Missing data produces a beautifully designed unavailable state, NEVER invented traces or zero-cost metrics.
6. Decision Report gets the final visual emphasis. Keep, Refactor, and Insufficient Evidence use identical typography and visual dignity.
7. The outcome is a limited recommendation. The independent per-arm VERIFIED/REJECTED/INSUFFICIENT_EVIDENCE status is a different kind of claim.
8. No artificial winner, fictional failure, unsupported cost savings, fake progress, or Meta-as-verifier narration.
9. Booking now → team permissions next → model hypothesis and challenge → fair A/B split → authenticated source/result → decision.
10. Implement everything in eligible ForeCode code as newly authored work; planning prototypes are reference, not transplantable assets.

## Signature trace anatomy

- **Requirement diamond:** amber, explicit human-confirmed upcoming team-permission task; never an observed production request.
- **Shared trunk:** one frozen task, same task digest per arm.
- **A lane:** credible unchanged source before the downstream agent.
- **B lane:** human-reviewed Meta-informed preparation and its separately counted upfront cost.
- **C lane:** only when a real equally roadmap-aware baseline exists and Study M is valid; never extrapolate from A/B.
- **Nodes:** source-backed path/grouping with known/proposed/observed state and completeness notice. Focus one node to view path, reason, selected phase, source revision, unknowns.
- **Phase selector:** BEFORE → PREPARED → AFTER; source-backed when hashes/files genuinely exist. B's proposed-prep outline is NOT an authenticated prepared tree. A's unchanged baseline is not an extra preparation run.
- **Resolution stroke:** points to report without changing color by winner. Independent receipts determine proof.

Interactive controls: Choose A/B; focus module; switch source stage; inspect shared task and comparability; open evidence; read report. Preserve keyboard navigation and text alternatives. Graph may animate only 220–320 ms on explicit selection, never autoplay fake execution. Reduced-motion user sees the same meaning instantly.

## Composition details

**Landing:** editorial left hero + precise right change-trace artifact. Headline: “The code works today. Will it survive tomorrow?” Sentence: “A booking app is about to gain team permissions. ForeCode tests whether an architecture change is worth making first.” Primary CTA: “Explore the booking case.” One quieter “How the comparison works.” Below fold a single rule-separated three-beat strip (Define / Compare / Decide), not a grid of SaaS feature cards.

**Case opening:** NOW (genuine booking interaction, when safe), NEXT (confirmed permissions requirement), DECISION (prepare boundary or retain status quo). Potential security/rework risk labeled hypothetical. No invented observed failed authorization example.

**Lab:** dominant bounded source graph, optional proposed boundary drawn hollow/dashed, human intent revision and Meta-origin hypothesis/falsifier/counterexample clearly distinct. If Meta provider unavailable: “Meta reasoning not run.” No fake model transcript.

**Tournament:** common conditions, one large A/B fork, one measured-correctness rail plus one preparation/downstream/total rail. Missing study has clear NOT RUN and Unknown values. Both pass means correctness tie, never automatic efficiency victory. A/B does NOT establish unique Meta causality.

**Time Machine:** stage tabs plus chosen arm, real source paths/diff on right. Missing snapshots read “Source snapshot unavailable — no approved prepared/final tree,” instead of a counterfeit future graph. An optional graphical topology is subordinate to authenticated changed-file list.

**Evidence:** independent checks and source/run/task/receipt links, openly scoped, Meta interpretation in distinct context. No browser actions that execute agents, shell or protected grader.

**Decision Report:** a warm paper-toned long-form memo in the dark workbench. Same hero scale and neutral title color for all outcomes. Above fold: type of decision, headline, one-sentence basis; then two or three numbered evidence reasons, “What was tested,” “What remains unknown,” prep-inclusive actual cost only when measured, and “What to do next.” Deep links to case-scoped evidence. No score dial, confidence %, celebratory panel, fake action button, or bogus certificate.

## Report outcome logic, not a new grader

| Authenticated inputs | Recommendation headline | Required caveat |
| --- | --- | --- |
| Missing/invalid/unmatched/stale receipts or unequal conditions | Insufficient evidence to choose | Identify missing match or proof and next legitimate run |
| Both verified | Conditional Keep/Refactor ONLY when previously fixed criterion and complete comparable prep-inclusive measurements justify it; otherwise Insufficient | Always state correctness tie first |
| Only A verified, B authentically rejected, comparable | Keep current architecture for now | Only A passed required checks in this ONE study |
| Only B verified, A authentically rejected, comparable | Refactor before team permissions | Only B passed in this ONE study; account for B prep |
| Both rejected | Insufficient evidence to choose | Neither passed; harden and rerun |
| Valid C alongside A/B | Above Study F result, separate Study M | B vs A cannot establish Meta's added value |

Metric absence = Unknown, not zero. All claims must be traceable to published exact run/tree/receipt IDs. Display verifier statuses separately from report recommendation. Prototype-only illustrative outcome controls NEVER ship as real result selection.

## Priority-ordered implementation slices

**P0-A / shell and narrative:** new visual tokens, persistent chapter navigation, authentic booking case opening and confirmed future-intent connection. Preserve routes, current functional intent/Meta flow and evidence boundaries.

**P0-B / Decision Report:** read-only adapter from approved tournament/receipt projection, composed no-run default, explicit outcome matrix tests. This should be built before elaborate motion.

No scope-changing new services, fake login, extra booking fixture, new browser-controlled agent action, or editable grader verdict.

## Acceptance before implementation PR can be called complete

- Fresh visitor can identify today, future requirement, two paths and proof in 20–30 seconds.
- No “winner,” “saved time,” fake run, live model inference, or source-backed diff ever shown from a conceptual state.
- An invalid/absent study displays elegant inconclusive report; both-pass always displays correctness tie.
- Authenticated A-only/B-only/both-failed states are explained accurately; stale run and missing/forged receipts always abstain.
- Preparation, downstream, total separated with real units or Unknown. No numeric confidence fiction.
- Original architecture winning feels just as prestigious as prepared architecture winning.
- Keyboard navigation, visible focus, text alternatives, named active states, reduced motion, 1440×900/768px/390×844, independently scrollable graph, no document x-overflow.
- Print report legible; no data leakage, invented private oracle details, or client-side verification authority.
- Verify any real screenshots/demo claims against approved source-bound evidence; planning HTML prototype remains explicitly fictional.
